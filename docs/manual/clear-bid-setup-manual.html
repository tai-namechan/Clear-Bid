0. このマニュアルのゴールと全体像

最終的にこうなります。

1. 外部AI

提案文・抽出・返信案が、実際に応募して恥ずかしくない水準になる。

2. D1保存

案件・診断履歴・作業時間が、ブラウザを変えても消えない。

3. Access認証

インターネット上にあっても、自分以外はログインできない。

なぜこの順番？

まず AI キーを入れて「提案文の質」を確認し、次にデータを残す箱（D1）を作り、 最後に鍵（Access）をかけてから公開します。先に公開だけすると、中身の薄いアプリが外に出ます。

大事な注意
  • APIキーやパスワードは、チャット・スクリーンショット・GitHub に貼らない。
  • わからない英単語が出ても大丈夫。このマニュアルの通り進めれば動きます。
  • 画面の文言は Cloudflare / Anthropic 側の更新で少し変わることがあります。近い名前を探してください。

1. 準備するもの（アカウント・ツール）

必要なもの何のため費用の目安
GitHub アカウント + Clear Bid のリポジトリ プログラムを置く場所 無料
Node.js（22以上推奨）と pnpm パソコン上でアプリを動かす 無料
Anthropic アカウント 提案文などを賢くするAI 従量課金（少額から可）
Cloudflare アカウント 公開・データベース・自分専用ログイン 個人利用なら無料枠で足りることが多い
自分のメールアドレス Access で「自分だけ」許可するため —

1-1. Node.js が入っているか確認

1

ターミナル（黒い画面）を開く

Mac なら「ターミナル」、Windows なら「PowerShell」や「Windows Terminal」。

次を打ち込んで Enter します。

node -v
pnpm -v
成功の見た目

v22.x.x のような数字と、10.x や 11.x のような pnpm の数字が出ればOK。

出てこないとき

https://nodejs.org/ から LTS を入れて再起動。 その後 npm install -g pnpm で pnpm を入れます。

2. パソコンで Clear Bid を動かす

なぜ先にローカル？

インターネット公開の前に、自分のPCだけで「画面が開く」「診断できる」を確認します。 ここで動くと、あとの設定ミスを切り分けやすくなります。

1

プロジェクトのフォルダへ移動する

Clear Bid をクローン（ダウンロード）した場所で作業します。

cd /path/to/Clear-Bid

自分の環境では、実際のフォルダパスに置き換えてください。

2

依存パッケージを入れる

アプリが使う部品をまとめてダウンロードします。

pnpm install
なぜ？

package.json に書かれたライブラリを node_modules に入れる作業です。初回は数分かかります。

3

環境変数ファイルを作る

秘密の設定を置くための .env を作ります。

cp .env.example .env

Windows PowerShell の場合:

Copy-Item .env.example .env
なぜ .env？

APIキーはプログラム本体に直書きしません。.env は GitHub に上がらないようにしてあり、自分のPCだけが知っている設定ファイルです。

4

開発サーバーを起動する

自分のPC上でアプリを動かします。

pnpm dev

ブラウザで次を開きます。

http://localhost:3000
成功の見た目

Clear Bid の画面（ホーム / 診断 / 案件 / 自分）が開けばOK。この時点ではAIキーがなくても、簡易モード（フォールバック）で動きます。

3. Anthropic（外部AI）のAPIキーを取る

Anthropic は、Clear Bid が提案文や抽出を賢くするためのAIサービスです。 「APIキー」は、あなたのClear BidだけがAnthropicを使えるようにするパスワードみたいなものです。

1

Anthropic のサイトを開く

ブラウザで次を開きます。

https://console.anthropic.com/

  • 右上あたりの Sign in / Log in（ログイン）をクリック
  • Google やメールでアカウント作成・ログイン
  • 初回なら利用規約に同意し、必要なら支払い方法（Billing）を登録
なぜ支払い登録？

無料枠だけでは足りない場合や、安定利用のためにカード登録が必要なことがあります。まずは少額の利用上限を設定しておくと安心です。

2

API Keys 画面へ行く

キーを発行するページを開きます。

  • 左メニュー（または設定メニュー）から API Keys をクリック
  • Create Key（キーを作成）をクリック
  • 名前はわかりやすく clear-bid-local などにする
  • 表示されたキー（だいたい sk-ant- で始まる長い文字列）をコピー
超重要

キーは画面に一度しか出ないことが多いです。パスワード管理アプリやメモに保存してください。 GitHub や Slack に貼ると危険です。漏れたらすぐ削除して作り直します。

4. ローカルで提案文を本番寄りにする

1

.env を編集する

Cursor / VS Code / メモ帳などでプロジェクト直下の .env を開きます。

次のようにします（キーは自分のものに置き換え）。

AI_PROVIDER=auto
ANTHROPIC_API_KEY=sk-ant-ここに貼る
AI_MONTHLY_BUDGET_USD=3

AUTH_BYPASS=true
DEV_USER_EMAIL=あなたのメール@example.com
項目入れる値意味
AI_PROVIDERautoキーがあれば Anthropic、なければ簡易モード
ANTHROPIC_API_KEYsk-ant-...AIを使うための鍵
AUTH_BYPASStrueローカルではログイン省略（開発用）
DEV_USER_EMAIL自分のメールローカル時の仮ユーザー名
2

サーバーを再起動して確認

設定変更後は、いったん止めてから起動し直します。

  • ターミナルで Ctrl + C（Macも同じ）で pnpm dev を止める
  • もう一度 pnpm dev
  • ブラウザで http://localhost:3000/api/health を開く

次のようになっていればOKです。

{
  "ok": true,
  "anthropicConfigured": true,
  ...
}
実案件テスト

画面の「診断」で、実際の募集文を貼って提案文まで進めてください。 テンプレっぽさが減り、あなたのスキル・実績を踏まえた文になっていれば成功です。

5. Cloudflare にログインして準備する

Cloudflare は、Clear Bid をインターネットに置いて動かす場所です。データベース（D1）と、自分専用ログイン（Access）もここで作ります。

1

アカウント作成 / ログイン

https://dash.cloudflare.com/sign-up

  • メールアドレスで Sign up（新規）または Log in
  • ダッシュボード（管理画面）が開けばOK
2

パソコンから Cloudflare にログインできるようにする（wrangler login）

ターミナルから Cloudflare を操作するための許可です。

pnpm exec wrangler login
  • コマンドを実行するとブラウザが開く
  • Allow（許可）をクリック
  • ターミナルに成功メッセージが出ればOK
なぜ？

このあと「データベース作成」「公開」をコマンドで行うため、あなたのCloudflareアカウントへの操作権限が必要です。

6. D1データベースを作る（データを消さない箱）

いまローカルだけだと、データはブラウザの localStorage（その端末の中）にあります。 D1 は Cloudflare 上のデータベースで、スマホや別PCからでも同じ案件履歴を見られるようにします。

1

D1 を作成する

プロジェクトフォルダで次を実行します。

pnpm exec wrangler d1 create clear-bid

成功すると、だいたい次のような情報が表示されます。

[[d1_databases]]
binding = "DB"
database_name = "clear-bid"
database_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
やること

database_id の長い英数字をコピーして控えてください。次の章で使います。

2

（任意）ダッシュボードでも確認する

視覚的に確認したい人向けです。

  • Cloudflare Dashboard を開く
  • 左メニューで Workers & Pages（または Workers）をクリック
  • D1 をクリック
  • clear-bid という名前のデータベースがあることを確認

7. 設定ファイルにデータベースIDを書く

Clear Bid に「どのD1を使うか」を教えます。

1

wrangler.jsonc を開く

プロジェクト直下のファイルです。

  • Cursor / VS Code の左のファイル一覧で wrangler.jsonc をクリック
  • REPLACE_WITH_D1_ID という文字を探す
  • さっき控えた database_id に置き換える
"d1_databases": [
  {
    "binding": "DB",
    "database_name": "clear-bid",
    "database_id": "ここにコピーしたID",
    "migrations_dir": "db/migrations"
  }
]
なぜ？

binding: "DB" は、プログラムから「DBという名前でこのデータベースを使う」という意味です。 IDを間違えると、保存したつもりでも別の場所を見に行ったり、エラーになります。

GitHub に上げてよいか

database_id 自体は秘密鍵ほど危険ではありませんが、リポジトリが公開（Public）なら注意。 Private リポジトリ前提で進めるのが安心です。APIキーは絶対にこのファイルへ書かないでください。

8. テーブルを作る（マイグレーション）

データベースを作っただけでは「空っぽの箱」です。 マイグレーションは、箱の中に「ユーザー」「案件データ」などを入れる棚（テーブル）を作る作業です。

1

本番（リモート）のD1に棚を作る

インターネット側のデータベースへ反映します。

pnpm db:migrate:remote

確認を聞かれたら y や Yes を選びます（表示に従ってください）。

成功の見た目

0001_init などが Applied / success と出ればOK。

2

（任意）ローカル用D1にも作る

ローカルでもD1を試したいとき。

pnpm db:migrate:local

9. Cloudflare Access で自分だけ入れるようにする

Access は「門番」です。Clear Bid のURLを知っていても、許可したメールでログインした人だけ中に入れます。 自分専用の仕事道具なので、ここは必ずやります。

1

Zero Trust を開く

Access の管理画面に入ります。

  • https://one.dash.cloudflare.com/ を開く
  • 初回ならチーム名（Team name）を決めます。例: yourname
  • このチーム名が後で CF_ACCESS_TEAM_DOMAIN になります（例: チーム名が namety なら namety）
なぜチーム名が必要？

Access のログイン画面や証明書の住所（ドメイン）が https://チーム名.cloudflareaccess.com になるためです。

2

Application（守るアプリ）を作る

Clear Bid のURLに門番を立てます。

  • 左メニュー Access → Applications
  • Add an application をクリック
  • Self-hosted を選ぶ
  • Application name: Clear Bid
  • Session Duration: 例 24 hours（好みで可）
  • Application domain / URL:
    あとでデプロイして分かる Workers のURL（例: clear-bid.<your-subdomain>.workers.dev）
    まだデプロイ前なら、先に仮で作って後から直してもOK。または次の章のデプロイ後に戻って設定
  • Next
3

Policy（誰を通すか）を作る

自分のメールだけ許可します。

  • Policy name: Only me
  • Action: Allow
  • Include の条件で Emails を選ぶ
  • Value に自分のメールアドレスを入れる（例: you@example.com）
  • Next → 確認して Save / Add application
なぜメール指定？

「リンクを知っている人なら誰でも入れる」状態を防ぐためです。副業の案件情報や金額が入るので必須です。

4

AUD（Audience）を控える

アプリ側が「正しい門番の通行証か」を確認するためのIDです。

  • Applications 一覧で作った Clear Bid をクリック
  • Overview や設定画面で Application Audience (AUD) を探す
  • 長い文字列をコピーして控える

このあと使う値は2つです。

変数名値の例どこで取る
CF_ACCESS_TEAM_DOMAIN / NUXT_CF_ACCESS_TEAM_DOMAIN namety（チーム名だけ） Zero Trust のチーム名。.cloudflareaccess.com は付けない
CF_ACCESS_AUD / NUXT_CF_ACCESS_AUD 長い英数字 Application の AUD

10. 秘密情報（Secrets）を Workers に入れる

本番では .env は使えません（あなたのPCの中だけのものだから）。 Cloudflare Workers の「Secrets（秘密の設定）」に入れます。

順番のコツ

Secrets はデプロイ後でも設定できます。ただし Access を有効にする前に、いったんアプリをデプロイしてURLを確定させる流れがわかりやすいです。 ここでは「値の意味」を先に覚え、次の章でデプロイ → Secrets 投入 → Access有効化、でもOKです。

入れるもの一覧

Secret / 変数名入れる内容なぜ必要
NUXT_ANTHROPIC_API_KEY sk-ant-... 本番でも賢い提案文を出す
NUXT_AI_PROVIDER auto キーがあるとき Anthropic を使う
NUXT_CF_ACCESS_TEAM_DOMAIN チーム名（例 namety） Access の通行証を検証するため
NUXT_CF_ACCESS_AUD AUD文字列 このアプリ宛の通行証か確認するため
NUXT_AUTH_BYPASS false 本番で門番をスキップしない

方法A: ダッシュボードで入れる（見た目がわかりやすい）

A

Workers の設定画面から追加

デプロイ後に Worker 名 clear-bid が見える前提です。

  • Cloudflare Dashboard → Workers & Pages
  • clear-bid をクリック
  • Settings タブをクリック
  • Variables and Secrets（変数とシークレット）を開く
  • Add → 種類を Secret にして名前と値を入れる
  • 上の表を1つずつ追加して Save / Deploy

方法B: コマンドで入れる

B

ターミナルから Secret を登録

一度ビルドしてから実行します（設定ファイルの場所の都合）。

pnpm build
pnpm exec wrangler secret put NUXT_ANTHROPIC_API_KEY --config .output/server/wrangler.json
pnpm exec wrangler secret put NUXT_CF_ACCESS_AUD --config .output/server/wrangler.json
pnpm exec wrangler secret put NUXT_CF_ACCESS_TEAM_DOMAIN --config .output/server/wrangler.json

実行すると「値を入力してください」と出るので、貼り付けて Enter します（画面には伏字になることが多いです）。

通常の変数（Secretでなくてよいもの）は Dashboard の Variables で:

NUXT_AI_PROVIDER=auto
NUXT_AUTH_BYPASS=false

11. デプロイ（インターネットに公開）

デプロイとは？

あなたのパソコンの中にあるアプリを、Cloudflare のサーバーにアップロードして、URLで開けるようにすることです。

1

公開コマンドを実行

プロジェクトフォルダで:

pnpm deploy

内部ではビルドのあと wrangler deploy が走ります。初回は1〜数分かかります。

成功の見た目

最後に https://clear-bid.xxxxx.workers.dev のような URL が出ます。これを控えます。

2

Access の Application URL をこのURLに合わせる

まだ Access を作っていない / URLが仮だった場合はここで確定します。

  • Zero Trust → Access → Applications → Clear Bid
  • Application domain を、今出た Workers URL にする
  • Save

12. 公開後の動作確認

1

門番が出るか確認

ブラウザのシークレットウィンドウで Workers URL を開きます。

  • Cloudflare Access のログイン画面が出る
  • 許可した自分のメールでワンタイムコード等ログイン
  • Clear Bid の画面が開く
門番なしで誰でも見えたら

Access の Application URL が違うか、まだ未作成です。すぐに Access を設定してください。 また NUXT_AUTH_BYPASS が true のままなら false に直します。

2

ヘルスチェック

ログイン後に次を開きます（Access通過後）。

https://（あなたのURL）/api/health

理想:

{
  "ok": true,
  "persistence": "d1",
  "anthropicConfigured": true,
  "accessConfigured": true
}
3

保存ができるか確認

「自分」タブでプロフィールを保存し、別ブラウザ（またはシークレット）で再ログインして残っているか見ます。

成功

プロフィール画面の「接続状態」が Cloudflare D1 になっていて、データが残っていればOK。

13. 日々の使い方

  1. 公開URLを開き、Access でログインする
  2. 「自分」でスキル・実績・稼働条件を入れる（提案文の材料）
  3. 気になる案件の募集文をコピーして「診断」に貼る
  4. 抽出を確認・必要なら手直し → 診断 → 提案文をコピーして応募
  5. 実際に応募したら「応募済みとして記録」を押す（コピーだけでは応募済みにならない）
  6. 返信が来たら案件詳細の「返信」に貼って回答案を作る
覚えておくこと

Clear Bid は自動応募しません。最終的にボタンを押すのはあなたです。 危険案件のBLOCKや金額計算も、AIではなくアプリのルールが担当します。

困ったとき

症状まず疑うこと対処
anthropicConfigured: false キー未設定 / 名前間違い ローカルなら .env の ANTHROPIC_API_KEY。本番なら NUXT_ANTHROPIC_API_KEY
persistence: "local" のまま D1未作成 / ID未記入 / マイグレーション未実施 章6〜8をやり直す。デプロイし直す
401 Unauthorized Access未ログイン / AUD不一致 / bypass誤設定 正しいメールでログイン。AUDとチーム名を見直す
提案文がテンプレっぽい フォールバック動作中 キー設定と /api/health を確認。プロフィール実績を充実させる
pnpm deploy 失敗 未ログイン / database_id が REPLACE のまま wrangler login と章7を確認
データが消えたように見える 別ユーザー / 別ブラウザのローカルキャッシュ Accessのメールが同じか確認。D1同期後は再ログインして確認

最終チェックリスト
